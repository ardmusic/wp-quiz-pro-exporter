## 2024-07-28 - Decoupling Interactive Elements and Localized Feedback inside WordPress Forms
**Learning:** Nesting multiple interactive controls like `<select>` and `<input type="submit">` inside a single `<label>` is bad for accessibility because it confuses screen readers. Proper semantic labeling requires keeping interactive elements separate and linking the label directly using `for` and `id`. Additionally, handling loading states for CSV export/download forms (which don't reload the page on submit) requires wrapping interaction logic in the form's `submit` event (instead of the button's `click` event) and disabling the button inside a brief `setTimeout(..., 0)` to allow the browser to initiate the download request successfully.
**Action:** Always decouple interactive elements, use distinct labeled tags with WordPress `screen-reader-text` utility class where visual representation is implicit, and handle loading state transitions inside `submit` events with a deferred disabling timeout (e.g. `setTimeout(..., 0)`) paired with automatic recovery timeout for AJAX/download handlers.
