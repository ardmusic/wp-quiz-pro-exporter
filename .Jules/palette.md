## 2024-08-14 - Loading Feedback & A11y Separation for Plugin CSV Export
**Learning:** For actions like CSV generation (handled via POST/admin-post.php with attachment headers), the browser triggers a file download without changing the page context. If a user submits, they receive no feedback that the download is processing, potentially leading to repetitive clicking. Disabling the submit button instantly on click can sometimes block form data submission in certain browsers; therefore, the ideal micro-UX pattern is to catch the form submit, update the value, and use a zero-timeout (`setTimeout(fn, 0)`) to disable the button to let the browser submit the form correctly. Additionally, nesting a select field and button inside a `<label>` can confuse screen readers; separating them and utilizing explicit `.screen-reader-text` labels alongside ARIA labels offers superior accessibility.
**Action:** Always intercept interactions via form's `submit` event rather than the button's `click` event. Use `setTimeout(..., 0)` to disable the button post-submission and use standard localized objects (via `wp_localize_script()`) for dynamic loading strings in JS. Keep interactive components structurally distinct inside `<fieldset>`/`<legend>` structures.
