## 2024-07-19 - Accessible Form Markup & Micro-UX Transitions
**Learning:** Avoid nesting select and input control elements directly within a single `<label>` element. It breaks standard assistive technology screen reader flows because a label should uniquely identify a single control element. Utilizing `.screen-reader-text` classes native to WordPress allows for clear visually-hidden labels that maintain proper accessibility. Also, localized JS parameters passed via `wp_localize_script()` should avoid using raw HTML entities like `&hellip;` because when assigned via `.val()` or `.text()` in jQuery/JS, the entity may display literally to the user rather than being rendered as characters (use literal periods/symbols instead).
**Action:** Always structure form components with unique `<label>` attributes mapping explicitly to single target inputs/selects via `for` and `id` bindings. For localized values in JavaScript, use clean string literals (e.g. `...` instead of `&hellip;`).
