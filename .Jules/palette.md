## 2025-01-20 - Accessible Form Design and Loading States in WordPress Plugins
**Learning:** In WordPress administration views, nesting multiple interactive form elements (like `<select>` and `<input type="submit">`) inside a single `<label>` element degrades accessibility and makes form fields harder for screen readers to associate correctly. Additionally, during administrative file downloads (such as CSV exports), standard JS-based submit button disabling can prevent form submission if done too early. Disabling the submit button within a `setTimeout(..., 0)` block inside a form's submit listener ensures the browser processes the native form submission prior to disabling the interface.
**Action:** Always separate `<label>` elements from form control elements, associating them explicitly via the `for` and `id` attributes. Use standard WordPress `.screen-reader-text` inside the label to hide assistive text from visual view while maintaining a11y compatibility. Ensure loading states on export buttons are managed with a slight delay (`setTimeout`) and automatically re-enabled (using `setTimeout` of 2000ms) to ensure smooth user experience since file downloads do not trigger a page reload.
