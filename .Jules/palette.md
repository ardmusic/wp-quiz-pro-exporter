## 2024-08-10 - Enhancing Screen Reader Accessibility & Asynchronous Button Loading Feedback in WordPress Admin
**Learning:** Nesting interactive elements like `<select>` and `<input type="submit">` inside a `<label>` block is invalid HTML markup and confuses screen readers. Standard WordPress `.screen-reader-text` classes should be used to provide hidden but descriptive labels instead of wrapping everything in a single, invalid label. Additionally, since WordPress CSV exports trigger file downloads asynchronously without triggering page refreshes, providing immediate loading state feedback (changing button value and disabling it) with a micro-UX automatic re-enable timeout (e.g. 2000ms) prevents double-submits while remaining functional.
**Action:** Always verify that labels only wrap a single form control or use the `for` attribute referencing an element `id` cleanly, rather than nesting multiple controls. For asynchronous browser-triggered actions like CSV exports, always implement a loading-and-restore timeout in JavaScript to keep the interface highly responsive and accessible.
