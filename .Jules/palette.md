## 2024-07-26 - Accessible Multi-Interactive Labels & Async Form UI Feedback in WordPress Plugins
**Learning:** Nesting interactive form elements (like `<select>` and `<input type="submit">`) inside a single `<label>` is bad for accessibility because it causes assistive technologies to associate the label label text poorly or trigger multiple focuses. In addition, when executing async actions or page-unload-free actions like downloading CSV exports via `admin-post.php`, updating the submit button state with immediate disabling can block the browser form submission process.
**Action:** Always decouple interactive elements by defining explicit `label` elements targeting only their specific inputs using `for` and `id`, using standard WordPress `.screen-reader-text` CSS class for visual layout cleaning. Attach the loading state/disable logic on the form's `submit` event rather than the button's `click` event, disabling the button only after a `setTimeout` with 0ms delay to allow the browser to initiate the submission first, and then restore the state via an appropriate timeout.
