## 2024-07-18 - Nested Element Labels and Async Submit Behavior
**Learning:** Placing multiple interactive elements (such as select dropdowns and submit buttons) within a single `<label>` tag severely limits screen reader accessibility and breaks standard element focus behavior. Separating interactive elements, providing screen-reader-text explicit labels, and using correct ARIA labels for icon-only buttons solves this cleanly. Additionally, when designing disabled button loading states for background downloads (like CSV exports that do not trigger a browser page reload), using a `setTimeout(..., 0)` inside the form's submit event allows the browser's form action to fire before disabling the submit button, preventing submission blocks. A standard 2000ms timeout can then be used to restore the button's interactivity and text.
**Action:** Always verify label element structures to ensure a 1:1 pairing with inputs using the `for` attribute and avoid nesting. Always attach submit-disabled interactions to form submit events rather than button click events and execute the disable logic within a immediate timeout.
