## 2024-07-29 - Form Submit Interception and Button Loading State
**Learning:** For background tasks (like file downloads) triggered by forms, changing the submit button's disabled state/text inside a `.on('submit')` handler must be wrapped in `setTimeout(..., 0)`. Disabling the submit button inside a synchronous submit handler can prevent the form from submitting correctly or transmitting the button's name/value to the server. Re-enabling the button after a reasonable timeout (e.g., 2000ms) is ideal for downloads that do not trigger a page reload.
**Action:** Always intercept interactions using the form's `submit` event rather than the button's `click` event. Use `setTimeout(..., 0)` to yield control back to the browser so the submit request starts before altering button attributes, and use a timer to gracefully restore the button's initial state.

## 2024-07-29 - Accessibility and Screen-Reader Compliance in WordPress Form Elements
**Learning:** Multi-interactive form layouts should avoid nesting `<select>` or `<button>` elements within a single `<label>` element, as this interferes with screen readers. Instead, separate them and associate the label with the input/select via the `for` and `id` attributes. Additionally, visual-only icons or Unicode entities used as button text (e.g., `&#8680; CSV`) must be paired with an `aria-label` to ensure screen-reader clarity.
**Action:** Follow clean HTML standards by keeping interactive form controls distinct and applying `aria-label` or `.screen-reader-text` elements where visual context is missing for screen readers.
